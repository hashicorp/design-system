## Application implementation

The website application is based on the overarching idea of having markdown files under `docs` that are pre-processed, parsed, and converted to a website in which the web pages and the navigation are automatically generated.

There are two key moments in this process:
1. At build time the markdown files are processed and
- Converted to JSON format and stored in `dist` according to their filesystem structure
- Pre-processed to generate a TOC ("table of contents") JSON file, also stored in `dist`. Pre-processing is done via specific functions/modules plugged into the Ember build system for the website application. In this step there is no HTML involved, only data (their frontmatter, their markdown content, their organization in the folder).

Related files:
- `lib/markdown`

2. At run time the JSON files are accessed by the web application to:
- Build the website navigation using the page-level TOC file generated at run time
- Render the web pages using the JSON file as source, associating the URL with its position in the filesystem. This post-processing is done via Showdown.

Related files:
- `app/controllers/show.js`
- `app/shared/showdown-config.js`

## Markdown processing

The key methodology for how markdown files from `docs` are processed is through the idea of a "show" entity which contains a router, controller, and template.

- `app/routes/show.js` is a route that acts as catch-all for all the non-standard pages (see "Routing").
- `app/controllers/show.js` is a controller that is responsible for taking the data from the model, processing it if needed, and converting the markdown content to HTML (see "TOC generation").
- `app/templates/show.hbs` injects the converted HTML (plus the page-related navigational elements) in the main content area using a special DynamicTemplate component (see "DynamicTemplate component").

## DynamicTemplate component

The `DynamicTemplate` component in `app/components/dynamic-template.gjs` is a special "component" that can inject at runtime in memory a component into the Ember app, using a special syntax provided by Ember.

The `DynamicError` component in `app/components/dynamic-error.gjs` is used to catch errors when the template compilation triggers an error.

## Routing

There are three main route categories in `app/router.js`:
- **Standard routes** - (custom pages, eg. `about`, `foundations`, `support`, etc.)
- **Error route** - The `error` route used for when an error occurs in the Ember application.
- **Show route** - The `show` route catches everything else and tries to render a page loading a content JSON file at the exact same path as the one matched by the `*path` wildcard

## TOC generation

- **Global TOC**
  - Generated by `lib/markdown/table-of-contents.js`
  - Saved to `dist/toc.json`
  - Used to build the global sidebar navigation
- **Page-level TOC**
  - Generated (in memory) at runtime by the application
  - Looks for all the <h2> and <h3> headings in the current page, and adds them to the sidecar element in the page
